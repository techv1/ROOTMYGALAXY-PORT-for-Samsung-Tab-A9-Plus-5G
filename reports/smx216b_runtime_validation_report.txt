1. STACK LIFECYCLE & VMAP_STACK ARCHITECTURE
====================================================================================================
- CONFIG_VMAP_STACK Behavior:
  [VERIFIED_STATIC] The kernel enables CONFIG_VMAP_STACK=y.
  Thread stacks are 16KB (4 pages) virtually mapped with guard pages on both sides.
- Allocation / Teardown Path:
  [VERIFIED_STATIC]
  * Allocation: dup_task_struct (0xffffffc0102f4068) -> alloc_thread_stack_node.
  * Teardown  : put_task_stack (0xffffffc0102f04b0) -> free_thread_stack (0xffffffc0102f3ea4).
- Per-CPU Stack Cache:
  [VERIFIED_STATIC]
  * cached_stacks array is located at 0xffffffc012668be0 (per-CPU pointer accessed via tpidr_el1 + 0xbe0).
  * In free_thread_stack (0xffffffc0102f3f50):
    0xffffffc0102f3f50: mrs  x9, tpidr_el1
    0xffffffc0102f3f54: ldr  x10, [x19, #0xb08]      ; x10 = stack vm_struct
    0xffffffc0102f3f58: add  x9, x9, x21             ; x21 = &cached_stacks
    0xffffffc0102f3f60: ldxr x22, [x9]
    0xffffffc0102f3f6c: stxr w11, x10, [x9]          ; atomically saves freed stack into per-CPU cache
  * A newly created thread on the same CPU immediately re-allocates the most recently freed stack
    from cached_stacks without memory re-zeroing, preserving stale data patterns across invocations.

3. QEMU FEASIBILITY ASSESSMENT
====================================================================================================
[HARDWARE_REQUIRED]
- Can the extracted kernel boot stand-alone in generic QEMU (e.g. qemu-system-aarch64 -M virt)?
  * Result: NO.
  * Reason:
    1. Qualcomm QGKI SoC Dependency: The kernel depends on proprietary Qualcomm SM6375 platform clock,
       power management (SPM/LPM), and inter-processor communication (SMP2P/SMD/QMI/RPMh) drivers.
    2. Missing Device Tree Blob (DTB): The extracted boot.img (Header v3) contains only the kernel
       payload and ramdisk. The Device Tree Blob (DTB) is located in the separate vendor_boot or dtb
       partition, which is not present in boot.img.
    3. Generic QEMU virt machine lacks Snapdragon 695 platform peripherals, causing immediate boot halt
       at platform device probe.
